## Claim

**Prop 1.** Let Q be acyclic, A = kQ/I with I generated by relations of length >= 2, i a vertex with an out-arrow, A_i the arrows out of i. For a target v put K(v) = red(Z_1 e_i)(v), the first-letter parts z_0 = sum eps_(r,p) p.rbar_r of degree-1 cycles z = z_0 + sum_alpha z_alpha alpha of Oppermann's model, and Ker(v) = the vector space step 7 solves for (`_kernelOverIdeal`: eps with sum eps (r/alpha) s in I for every alpha). Then **K(v) = Ker(v) as subspaces of the same coordinate space {(r, p)}** (proof; tested in 7 479 pairs): same coefficients, same orientation, no transpose, no extension by paths, where K is built from my transcription of Oppermann's Z_1, B_1. Consequently (Lemma L below) the ideal of kM_0 generated by Oppermann's differentials of degree-1 arrows (steps 4, 5, 6, through, and d of the degree-2 arrows x out of i) equals the ideal generated by the repo's steps 4-7, and, taking Def. 3.2 and Thm 1.1 (v1, End(T) = H_0(kM), E-189) as read, plus generation (E-168), the repo's rewrite, up to the cleanup `reduce`, presents End(T) for acyclic parents. This makes the identification G2 of E-181 a theorem for acyclic parents, parallel arrows included. It does NOT say the repo's cleanup output is minimal on cyclic children, nor anything about cyclic parents, nor which of End(T), End(T)^op the quiver convention gives.

Generator count (tested, not proved): with g(v) = dim Z_1(i->v)/(B_1 + Z_1 rad + rad Z_1), the number of degree-2 arrows i->v of Q^(2) (Constr. 2.2), the repo returns r7 >= g in every pair (953 vs 853 in all; excess in 76 pairs); the excess elements are the rbar.s with s in I of Lemma L, which `reduce` drops. After `_minimalGenerators` the number of relations out of i* equals g in 7 478 of 7 479 pairs; the exception is a cyclic child (below).

## Evidence

**Proof (acyclic Q).** Degrees: ||phi|| = |phi| - [s(phi)=i] + [t(phi)=i], alpha* has degree 0, ||alpha phi|| = ||phi|| - 1, ||phi alpha^{-1}|| = ||phi|| + 1 (Oppermann Sect. 3, `mutation.tex` l. 313-385, read). *Step 0, the degree-1 arrows of M and their differentials*: (a) beta into i, |beta| = 0: d = sum_alpha alpha* (alpha beta), all signs +; (b) phi: i->j', |phi| = 1 (a relation): the arrow phi alpha^{-1}, d = (+) phi alpha^* - dphi/alpha (here ||phi|| = 0 and t(phi) != i), i.e. rbar alpha* = r/alpha; (c) phi into i, |phi| = 1: alpha phi, d = alpha red(dphi), i.e. the relation extended by alpha; (d) carried arrows with |phi| = 1 not touching i: d = dec red dphi, no Delta occurs because every degree-0 arrow out of i is in A_i; (e) x: i->v, |x| = 2, ||x|| = 1: dx = dec red dx. No other arrow has ||.|| = 1 (loops at i would add alpha phi beta^{-1}; acyclic excludes them). These are the repo's steps 4, 5, 6, through, 7 coefficient for coefficient (`procedure.py` 340-366: all + except the explicit - in 5), with Oppermann's right-to-left word order read as the repo's left-to-right; arrows keep tail and head, so there is no transpose in the formulas. *Step 1 (kernel)*: write z = z_0 + sum_alpha z_alpha alpha; every nonempty q starts with an arrow of A_i, so red keeps exactly the q-empty part z_0. d z_0 = sum_alpha (d z_0 / alpha) alpha in the free path algebra (admissible relations: no trivial path). z is a cycle iff d z_alpha = -(d z_0/alpha) for each alpha; d maps degree-1 words onto I, so lifts z_alpha exist iff (d z_0)/alpha in I for all alpha. That is the repo's kernel condition. *Step 2 (Lemma L)*: B_1 e_i is spanned by d(q rho_2 m rho_1 p) = q rho_2^el m rho_1 p - q rho_2 m rho_1^el p; red kills the first term (leading path nonempty) and the second unless q is empty, so red(B_1 e_i) = {rbar_r . s : s in I}. For acyclic Q, m, rho_1, p start at t(r) below i and never meet i, so rho_1 is a *carried* relation (it starts at t(r), not at i) and rbar_r s lies in the ideal of the carried relations, already among the generators. Z_1 e_i = sum p z_x q + B_1 e_i over the generators x of H_1 (Constr. 2.2), and red(p z_x q) = 0 unless q is empty, so K(v) = sum_x p red(z_x) + rbar.I. *Step 3*: hence ideal(Oppermann) = ideal(carried, 4, 5, 6) + (d x) and ideal(repo) = ideal(carried, 4, 5, 6) + (Ker) coincide.
**Weakest steps:** (i) the list in Step 0 is read from Def. 3.2 of v1, not re-derived from the paper's proof or compared with a later version; (ii) Thm 1.1's cancellation step stays cited (E-189); (iii) "g = every x has d x != 0 and independent" is data, not proof (an x with all q nonempty would have red = 0); (iv) Lemma L is proved only where no path from t(r) returns to i.

**Tests** (`theorist_g2exact.py`): K_opp computed in the free path algebra by nullspace (`Z_1`, `B_1`, extensions), Ker from `_kernelOverIdeal` in the same coordinates (r, old tail), subspace equality, 0 differences in 7 479 pairs. **Cycles.** (1) The one pair with minimal-out-count 2 > g = 1 (seed 12, i = 3, gate-admitted, ker f = 0 by hand) has a parent without cycle and a child with the 2-cycle 3<->5. Cartan with ALL paths (length <= 8, stable at 10) gives R C R^T - Cartan(child) = 0, so the rewrite is correct; the repo's `cartanDiscrepancy` shows 20 nonzero entries, and `_minimalGenerators` keeps a redundant relation (3,5)(5,6)(6,7) whose redundancy needs the non-simple path (3,5)(5,3)(3,6)(6,7). Cause: `allPathsBetween` is vertex-simple, so every ideal and Cartan computation on a cyclic quiver silently drops non-simple paths (E-181's 8 152 sweep is unaffected because LNA children are acyclic). So Prop 1 holds with a cyclic *child*, but that child is not a valid *parent* for the repo's tools. (2) Cyclic Nakayama parents C_n, all relations length L (n, L) = (3,4), (4,3), (4,5/4/3/4), (5,4), (3,3): 9 of 19 vertices raise KeyError (`_spliceOutVertex` splices only the first passage through i, and step 3's cyclic case is F-002), 10 are gate-refused, the rewrite then runs and fails Cartan at one or two entries of -1 (true-path Cartan, consistent with J != 0), 0 are gate-admitted with a running rewrite. Not shown: a cyclic parent where steps 1-7 run and the tails need non-simple paths.

**Can J = 0 be settled by proof?** Per step, yes, and it is already: J_i = {x in e_i A e_v : x rad A = 0} = ker(x -> (x alpha)_alpha), a linear-algebra condition on the parent alone (AI 2.32(b), E-099, E-171, and the `EXPERIMENTS.md` entry at line 525). For monomial parents the gate decides it (a kernel vector's path supports each lie in the kernel). With Prop 1, a step of an acyclic parent has J = 0 iff that kernel is 0, and then End(T) = the rewrite by theorem, not by test. So the premise "J = 0" on a printed path reduces to a finite check per edge plus three things more tests cannot close: (a) every parent on the path is acyclic, (b) the cancellation step of Thm 1.1 and the convention, (c) generation (E-168, proved per loopless step). Check (a) is a scan, not a theorem, and it is the live gap: a path through a child with an oriented cycle leaves Prop 1's hypothesis, and the repo's own `tiltingPlus`/Cartan tools are then unreliable on it.
