## True?

The hit claim holds up. Two points the text gets wrong or leaves open:

- **R is mis-described.** The code does not take the inverse of a recorded F step. It takes a forward step on the opposite algebra and dualizes back (`moves`, kind R). The needed fact is only that D(A) ~ D(B) iff D(A^op) ~ D(B^op), so R is a tilting step whenever F is. That is sound and does not depend on E-149's "inverse" convention; the "Claim" and "Next" wording ("R as the inverse of a tilting step", "test whether R really is a tilting step") should say so. The premise left standing is the one T10 asks about: J = 0 plus `tiltingPlus` implies derived equivalence. My replay re-tests the same predicates (and the necessary Cartan congruence), so it is not an independent derived-equivalence test; none exists in the repo. Say so once, in the Claim.
- **Parent membership is not shown.** The E-151 walk adds every key-kept child to the frontier, including J != 0 children (`add(ch, ...)` in the collector), so a depth-8 parent may descend from a depth-7 failing child. A hit proves the child is in the class; it proves the parent is only if the parent's own path from the LNAs is all J = 0. The sentence "the key-guard's failure on them is not a counter-example to 'the walk stays in one class'" needs that check, or should be cut to "the child is in the class". (E-151 puts first failures at parent depth 7, so depth-7 parents are clean; depth-8 parents are not covered.)
- Observation: in every search `stats` shows tp = 0 and key = 0. With J = 0 the `tiltingPlus` and key filters never fire, so the moves are "gate and J = 0" only. Not an error, but the text lists them as three active filters.
- The misses: bound 6 + 5 = 11 is correctly stated as a bound, not out-of-class evidence. The L = 11 control above shows 11 is reachable, so the bound is not trivially short.
