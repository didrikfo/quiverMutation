## True?

(a) I checked it line by line and found no gap. m = +1: chain maps Y -> Y[1] and Y -> P_i[1] are unconstrained, and the approximation gives the null-homotopies. s0 lands in sum P_t, which is a summand of D because t != v. m = -1: Hom(P_i, Y[-1]) = J_i. Hom(Y, Y[-1]) is a map sum P_t -> P_v in degree 0, and it vanishes by acyclicity. |m| >= 2 vanishes by degrees. Generation holds by the cone. The out-arrow-less case (Y = P_v[1], J_i = A(i, v)) also holds, and the sweep confirms it: every no-out-arrow vertex has inj = Hom, and the isolated ones are the 1 830 / 1 792 / 1 770 rows.

(b), the weakest step. The reading is right for uniform relations. `allPathsBetween` is vertex-simple, which on acyclic Q means all paths. Rows are the concatenated normal forms of pb, and normal forms are linear, so rank = dim im phi_i against quotientDim = dim A(i, v). **The uniformity assumption is load-bearing and nothing enforces it.** `procedure.relationsFrom` does not check it, and neither does `isTiltingAtVertex`. `arrowPaths.source/target` read only the first path of a relation. Counterexample: 1 -a-> 2 -b-> 3 -d-> 5, 4 -c-> 3, with one relation abd + cd. That relation is non-uniform and generates the ideal (abd, cd). At v = 3, `isTiltingAtVertex` returns **True** and the gate returns True. With the split presentation [abd], [cd], which is the same ideal, both return **False** (ab is in J_1). The input is illegal by the library's own `arrowPaths.isIllegalRelation` (True on it, False on the split form). So (b) stands within the stated scope ("generated by uniform combinations"), but the precondition should be explicit. Script: `scratchpad/nonuni.py` (not committed; 8 lines with `J.build`, reproducible from the description above).

(c) is E-128 L1 read contrapositively, and it is correct. The 0 COR failures across 3 seeds agree.

Overstatement: the note says "H-030's 8 over-admissions are … exactly … E-080's mechanism". E-327 splits them 5 E-080, 2 E-080 plus an extra path, and 1 E-112 two-arrow circuit (3277). All 8 are "J_i != 0 with no path in J_i", which is what (a) and (c) give. They are not all E-080's shape.
